# Репозиторий «Книга рецептов» (recipe-book)

Личное приложение для ведения книги рецептов для мамы. Работает как
одностраничный сайт, хранит данные в Supabase, готово к обёртке в десктоп
и APK.

## Состав

| Файл | Назначение |
|------|-----------|
| `recipe-book-site.html` | Главная страница приложения (одним файлом). |
| `supabase-recipe-schema.sql` | Схема базы + политики безопасности (RLS). |
| `supabase-fetch-recipe.ts` | Edge-функция для разбора рецепта по ссылке. |

> `book-of-recipes.html` — ранняя черновая версия без базы, можно удалить.

## Что уже сделано

- Рецепты с фото хранятся в Supabase (таблица `recipes`).
- Аккаунты — через **Supabase Auth**: пароли хранятся на сервере (захешированы),
  в браузере их нет.
- RLS включено на всех таблицах: личные рецепты видит и меняет только владелец,
  анонимный ключ доступа к данным не имеет.
- Настройки оформления (тема, палитра, фон, крупный текст, быстрые ингредиенты)
  привязаны к аккаунту и синхронизируются между устройствами.
- Защита от XSS через поле «фото».
- Разбор рецепта по внешней ссылке через Edge-функцию.

## Как развернуть

1. В панели Supabase (ваш проект) откройте **SQL Editor** и выполните
   содержимое `supabase-recipe-schema.sql` (**один раз**). Это создаст таблицы,
   включит RLS и триггер профиля.
   - ⚠️ Перед этим удалите прежние таблицы, если они отличались структурой
     (старая `recipes` имела текстовое поле `owner`, новая использует `owner_id`).
2. Разверните Edge-функцию для разбора по ссылке:
   - `supabase functions new fetch_recipe`, вставьте код из
     `supabase-fetch-recipe.ts`, затем `supabase functions deploy fetch_recipe`.
3. Откройте `recipe-book-site.html` в браузере или оберните в Capacitor/Electron.

## Конфигурация Supabase

В файле `recipe-book-site.html` в начале `script` есть две константы:
`SB_URL` (Project URL) и `SB_KEY` (anon public key). Они уже принадлежат вашему
проекту. Публичный anon-ключ безопасно хранить в клиентском коде — доступ
к данным ограничен политиками RLS, а не секретностью ключа.

## Безопасность

Этот репозиторий **публичный**, поэтому здесь ничего не спрятано «за закрытой
дверью» — защита строится на уровне базы данных. Что критично для безопасности
вашей копии:

- **Пароли НЕ хранятся в коде и в базе.** Регистрация/вход идут через
  Supabase Auth: сервер держит пароль в виде bcrypt-хеша, клиент хранит только
  токен сессии (JWT).
- **Анонимный ключ не имеет доступа к данным.** В `supabase-recipe-schema.sql`
  включено Row Level Security на всех таблицах (`profiles`, `recipes`,
  `user_prefs`, `staff`). Аноним не может читать личные рецепты, профили или
  настройки. Доступ — только через токен своего пользователя.
- **Личные рецепты видит и меняет только владелец** (политики по `auth.uid()`).
  Публичные рецепты (private=false) читают все аутентифицированные.
- **Админ-роли** — через таблицу `staff` (роли owner/admin/moderator),
  проверяются серверными функциями `my_role()`/`is_admin()`.

⚠️ **Чтобы всё это работало у вас**, обязательно выполните
`supabase-recipe-schema.sql` в своей базе. Пока RLS не включён (старая схема
без авторизации), данные открыты анонимному ключу — публикация кода этого
не меняет, но и не усугубляет: защита всегда на стороне вашей базы.

**Прежде чем открыть репозиторий**, проверьте:
1. База использует новый SQL с RLS (а не старую схему с открытым доступом).
2. Первый админ добавлен вручную в таблицу `staff` (id + email + роль owner).
3. Edge-функция `fetch_recipe` развёрнута, если нужен импорт по ссылке.
